# Media tokens

Three kinds of token, all compact JWS: header `{ "alg": "EdDSA", "typ": "JWT", "kid" }`,
signed with Ed25519 by the API, verified by the media plane against its static
public key ring (`MEDIA_TOKEN_PUBLIC_KEYS`: comma-separated `kid:base64pem`
pairs, where `base64pem` is the base64 of a PEM-encoded SPKI public key). The
signer's setting is `MEDIA_SIGNING_KEY` in the same form with the PKCS#8
private key. `iss` is the media plane's instance id (`MEDIA_INSTANCE_ID`, the
API's `MEDIA_ISSUER`).

Golden vectors: [`vectors/tokens.json`](vectors/tokens.json), generated by
`spec/scripts/media-vectors.mjs` from a test-only key that is in the file.
Ed25519 signatures are deterministic, so the vectors are stable. Every
implementation must accept and refuse exactly as they say, with
`now = vectors.now`.

## Verification, in this order

1. Three dot-separated base64url parts, a JSON object header with
   `alg: "EdDSA"` and a non-empty string `kid`. Otherwise `malformed`.
2. `kid` is an own key of the ring. Otherwise `unknown_kid`.
3. The signature verifies. Otherwise `bad_signature`. Nothing in the payload
   is read before this.
4. The payload is JSON with the expected `aud` (`wrong_audience`) and `iss`
   (`wrong_issuer`).
5. The exact claim set below, no other claims and no other grants
   (`bad_claims`).
6. Time, with 30 s skew: `exp + 30 <= now` is `expired`; `nbf - 30 > now` or
   `iat - 30 > now` is `not_yet_valid`; `exp - iat > 900` is `ttl_too_long`
   (join and control only; a media plane may lower the ceiling, the API mints
   600 s join and 60 s control tokens).
7. Join tokens only: the grant rules below (`bad_claims`), and a `human` on any
   transport but `webrtc` is `bad_transport`.
8. Join and control tokens: the `jti` is consumed. A second presentation is
   `replayed` (signalling) or 401 (control). WHIP bearers are not consumed;
   they are long-lived and checked by the authorize callback every time.

The reason is for the media plane's logs. A client is told only
`unauthorized` (or `replayed`).

## Join token (`aud: "media"`)

| Claim | Type | Rule |
|---|---|---|
| `v` | `1` | required |
| `iss` | string | the instance id |
| `aud` | `"media"` | |
| `room` | string, 1–200 | the room the token admits to |
| `identity` | string, 1–200 | unique within the room |
| `name` | string, ≤ 200 | optional display name |
| `kind` | `human`, `agent`, `egress`, `sip`, `ingress` | |
| `transport` | `webrtc`, `plain`, `pipe` | decides the transport type; a client cannot ask for another |
| `grants` | object | below |
| `jti` | string, ≥ 8 | single use |
| `iat`, `exp` | integer seconds | required |
| `nbf` | integer seconds | optional |

Grants (no other keys):

| Grant | Type | Meaning |
|---|---|---|
| `canPublish`, `canSubscribe`, `canPublishData` | boolean | required |
| `publishKinds` | `audio`/`video`/`screen` list | what may be produced; absent is any |
| `subscribe`, `visibleTo` | `{mode: all}`, `{mode: none}`, `{mode: allow\|deny, identities[≤500]}` | identity rules |
| `subscribeExempt` | boolean | non-human only, and only with `maxSubscriptions` |
| `maxSubscriptions` | integer 1–5000 | consumer ceiling |
| `subscribeKinds` | `audio`/`video` list, 1–2 | what may be received; enforced by the node on `joined`, `producerAppeared` and `consume` |
| `maxResolution` | `720p`, `1080p` | carried for the egress; the node does not act on it |
| `idleTimeoutSeconds` | integer 1–86400 | carried and echoed; the API runs the timer |
| `maxLiveViewers`, `maxActiveSources` | integer 1–100000 | carried; the API enforces them at mint time |

Grant rules: `subscribeExempt` never for `human`; `subscribeExempt` needs
`maxSubscriptions`; `subscribe`, `subscribeExempt`, `maxSubscriptions` and
`subscribeKinds` need `canSubscribe`; a non-empty `publishKinds` needs
`canPublish`.

What Senseplane mints:

| Who | `identity` | `kind` / `transport` | grants |
|---|---|---|---|
| capture page | `{source_id}:capture` | `human` / `webrtc` | `canPublish`, `publishKinds: ["video"]` or `["video","audio"]`, `maxResolution`, `maxActiveSources?` |
| WHIP publisher | `{source_id}:whip` | `ingress` / `webrtc` | as above |
| the camera's feed | `{source_id}:feed` | `egress` / `pipe` | `canSubscribe`, `subscribeExempt`, `maxSubscriptions: 4`, `subscribeKinds` |
| live viewer | `{source_id}:viewer:{session_id}` | `human` / `webrtc` | `canSubscribe`, `subscribeKinds: ["video"]` or `["video","audio"]`, `idleTimeoutSeconds`, `maxLiveViewers?`; `jti` = the session id |

An egress's join token carries `transport: "pipe"`: the media plane's own
egress leg, whatever that is inside the media plane (a pipe transport, a
plain RTP leg to the media plane's own network). The caller never dials it;
it only mints the token the egress joins with.

## Control token (`aud: "control"`)

Exactly `v: 1`, `iss`, `aud: "control"`, `jti` (≥ 8), `iat`, `exp`, optional
`nbf`. No room, identity or grants. One per call, single use.

## WHIP bearer (`aud: "whip"`)

`v: 1` (optional), `iss`, `aud: "whip"`, `room` (1–200), `authorize_url`
(http(s), ≤ 2048), `jti` (8–200), `iat`, optional `nbf` and `exp`. No TTL
ceiling: it is pasted into a camera once. Its signature is what lets the
ingress trust `authorize_url`; the authorize answer is where revocation and
limits are decided (`whip.md`).

## Callback tokens

The `callback.token` a room or egress request carries is the caller's own
business: the media plane echoes it and never parses it. Senseplane uses an
EdDSA JWT with `aud: "senseplane-media-callback"`, the room and source in its
claims, and no expiry (a feed can run for months); the API verifies it and
checks the body's room against it.
