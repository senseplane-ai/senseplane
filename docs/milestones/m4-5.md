# M4.5: live demo — results

Date: 2026-10-16. Done-when: a no-sign-up demo a website can embed on one
page: on a phone the page uses the phone's camera; on a laptop it shows a QR
code, then events and "ask" live on the same page; CORS limited to the
website's origins; video only; sessions up to 10 min; all data deleted 1 h
after the session ends; per-IP, per-session and global model-call limits
(ADR 0021).

## Implementation

- API (`api/src/routes/demo.ts`, migration 0006): one temporary account
  (`kind = demo`) per session with a video-only phone source and two preset
  watches; token 32 random bytes, stored hashed; IPs stored as an HMAC with a
  daily salt; SSE polls the database each second (status, events, a snapshot
  every 5 s, keep-alive); ask goes to memory for "when/did/…" questions or
  after the end, otherwise a live model look; sweeper every 30 s (expire →
  disconnect via media, cap → pause watches, +1 h → delete objects and the
  account).
- SDK: `SenseplaneDemo` (start, stream (SSE over fetch, token in a header),
  ask, end). A page uses it with `mediasoup-client` and the media signalling
  protocol to stream the visitor's camera.

## Found and fixed on the way

- React StrictMode ran the phone's capture effect twice; the second join
  replaced the first ("connection closed"). Guarded with a ref.
- CORS preflight refused `DELETE` (methods must be listed with a per-request
  CORS delegate).
- Fastify's own 4xx errors (e.g. an empty JSON body) came back as 500.
- A media plane with `MEDIA_RTC_PORT=0` (a port per transport) never completed
  ICE with Chrome on the test machine; a fixed WebRTC server port (the compose
  default, 40000) works.

The demo snapshot is a still every 5 s, not live video (signed-in accounts
have live view, ADR 0042).
