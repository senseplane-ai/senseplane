# Roadmap

What the open-source Senseplane does today and what comes next. Each milestone
has a test that says when it is done; results are in [`milestones/`](milestones/).

## Milestones

| | Milestone | Done when |
|---|---|---|
| M0 | **Foundations:** monorepo, licences, CI per layer, compose infrastructure, a tenancy skeleton (accounts, `account_id`, row-level security), `spec/` with the public schemas and the media contract | `docker compose up` works, CI is green, the browser-H.264-to-fMP4 spike has an ADR |
| M1 | **Phone to recording:** browser capture page (`mediasoup-client`), media control API and token auth, `POST /sources`, console QR page with the consent indicator, file-replay publisher | A phone streams, and the last minute plays back within 15 s of being captured |
| M2 | **Recording and playback:** ~6 s segments, an index built from `media.segment.written`, HLS ranges, clips, retention-based deletion (per account and per source), load test with the replay publisher | 24 h with no missing segments; any minute starts playing in under 2 s; a clip survives raw deletion; streams per node benchmarked |
| M3 | **Signal and perception:** analysis feed with masks, motion and audio, object detection and tracking, sound classification, zones, episodes, events, signed webhooks, sensor readings by push | Person events fire within 2 s, with a clip attached, delivered by signed webhook (on fixtures) |
| M4 | **Watches and understanding:** the watch spec, the VLM adapter (any OpenAI-compatible endpoint), `look` and `ask`, memory search, feedback | The package watch catches every delivery in a day of door footage with fewer than 3 false events; fewer than 50 model calls per camera per day; `what_happened` finds the courier |
| M4.5 | **Live demo:** a no-sign-up demo API (temporary account, one phone source, preset watches, live event stream, ask) that a website can embed | A phone streams from a web page, events and answers appear live, and everything is deleted after the session |
| M5 | **MCP and SDK:** 8 tools over stdio and remote (OAuth), TypeScript SDK, quick-start docs | Claude, Cursor and one more client call all 8 tools; spec-drift CI is green |
| M6 | **Grants, privacy, metering:** per-agent grants, privacy masks, audit log, export and deletion, usage records, quotas | A video-only grant gets an error on `listen`; masked regions are black in snapshots and model inputs; revocation within 60 s; usage per account matches a known test load within 1% |
| M7 | **More ingest:** WHIP (done: `whip` sources, per-source tokens with rotation, [WHIP ingest](ingest-whip.md), ADR 0034); RTMP with per-source tokens; MCP Registry listing | OBS and one push camera record for 24 h without gaps |
| Live | **Live view** (ADR 0042, done): watch a camera live in the browser over the media signalling protocol, no transcoding; video grant required, audio only with an audio grant; idle viewers closed; viewer-minutes metered; feature switch, viewer cap and allowance through the quota provider | A viewer sees frames within 2 s; a video-only grant gets no audio; an idle viewer is closed |
| M8 | **Bridge:** RTSP cameras over WHIP, outbound only, with health reports and a Docker image, and the Home Assistant integration for climate sensors (done, ADR 0045); pairing codes (done, ADR 0061); ONVIF discovery: cameras on the box's network listed (named after Home Assistant's) and added with their username and password, the stream that fits `max_resolution` picked (done, ADR 0063); next: remote updates | An ONVIF camera records within 2 min of pairing, with no router changes |
| T | **Telegram** (ADR 0059, done, [guide](telegram.md)): link a chat with a one-time code, watch alerts with a snapshot and buttons, mute, and questions from the chat as its own agent; one bot per server, polling (no public URL) or by webhook for several API processes; background work shared through Postgres (ADR 0058) | An alert reaches a linked chat with its snapshot, and a question asked there is answered within the chat's grants (on a fake Bot API) |
| A | **Activity timeline** (ADR 0057, done, [results](milestones/activity.md)): presence, sound and watch activities with a start and an end, recording coverage, `mode: track` watches and packs, one query engine for count, duration, absence, first/last, order and trends (REST, chat, MCP), checking history after the fact, `condition` and `digest` watches, sites | "How many meals today?", "How long did she sleep?" and "Is it quieter than usual?" are answered exactly, with evidence and coverage, on the fixtures |
| H | **Home box and more sensors** (ADR 0060–0063, built, [results](milestones/h.md); the run on a Green with real devices is next): readings beyond climate (on/off states, events, and any number with a unit) for doors, windows, motion, presence, leaks, smoke and CO, plugs and power, locks and buttons; the Home Assistant integration forwards all of them; the bridge as a Home Assistant add-on, so one always-on box (such as a Home Assistant Green, no radio sticks needed) relays IP cameras and forwards sensors; one pairing code for both; watches and questions across cameras and sensors ("the door opened and no one was on the porch camera", "the fridge wasn't opened by 10am"); a box or integration that goes offline shows as missing coverage, never as "nothing happened" | On a Home Assistant Green with no radio sticks, an RTSP camera and a Wi-Fi door sensor are linked with one code; "has the fridge been opened today?" is answered from the sensor; an absence watch says it can't be checked while the box is off |
| C | **Control, only when a person asks** (ADR 0067, built; the run on real devices is next): a person switches the devices Senseplane can reach, from the console, Telegram or the Android app, or by asking their agent (`list_devices`, `control_device`). Nothing is switched automatically: only a request can issue a command, so watches, workflows and jobs never control devices. Lights, plugs, fans, sirens, thermostats (10–28 °C) and blinds, through Home Assistant and Matter (a Matter Server or the built-in controller). Two switches, both off by default: an admin makes each device controllable, after a warning, and an agent needs the new **Control** permission, which "Read sensors" never includes. Locks, garage doors, gates and alarms wait for a person to confirm (2 minutes, then refused). Heaters, ovens, medical devices and machinery are never offered. 10 commands a minute per device. A box that doesn't take a command within 10 s answers "offline" and never runs it later. The state is read back after each command, so an answer never says "done" when it isn't. Every attempt, who asked, through what and the state afterwards is in the audit log | An agent with a Control grant turns on the hall light and the answer reports the new state; an agent without the grant gets an error; an unlock request waits for a person to confirm and is refused when they don't; every attempt is in the audit log |

## Planned features

- **Storage:** optional batched uploads (keep ~6 s segments for playback, upload them grouped into ~1-minute objects with a byte-range index) to cut object-store write operations about 10×.
- **Ingest:** SRT; the Android app on the Play Store (built: camera, relay for IP cameras and a sensor hub, ADR 0064); push cameras pick the camera stream that fits `max_resolution`, never transcoding (the bridge does for cameras added from its network, ADR 0063).
- **More sensors:** a documented, signed readings webhook for IFTTT, n8n, Zapier, ESPHome, Shelly and scripts, and MQTT in on the box from Home Assistant discovery and plain topics (done, ADR 0071, [recipes](sensors-webhook.md)); next: adding new Matter devices over Bluetooth, and checking revoked device certificates (the built-in controller adds shared devices with a code and checks their attestation, ADR 0065). Zigbee, Z-Wave and Thread radios stay with Home Assistant.
- **Open bridge outputs:** the box publishes Senseplane's events over MQTT in Home Assistant's discovery format, a person sensor per camera, its online state and an event per watch, when the account turns it on for that box (done, ADR 0071); next: the bridge sends to any WHIP server, re-serves RTSP locally and publishes its sensors over MQTT or a webhook, with Senseplane as one output among them.
- **Privacy:** per-account encryption keys (done, ADR 0066); face and plate blurring in snapshots and model inputs, per account and camera, and agents that only see blurred media (done, ADR 0068); next: our own plate model on YOLOX for plates worldwide, and blurred renditions of recordings.
- **SDKs:** Python SDK.
- **Understanding:** image embeddings; a "check history" tool in the chat. Count, duration, absence, first/last and trend questions and watches come with the activity timeline (milestone A).
- **More channels:** email, Slack, Discord, WhatsApp and ntfy as kinds of channel (ADR 0059), alongside Telegram.
- **Workflows:** "when this happens, do that", without code. Triggers: a watch firing, any event type (a person, a sound, a reading over a threshold), a camera going offline, or a schedule. Steps: call an HTTP API, send an email, SMS or WhatsApp, post to Slack or Teams, create a Jira or Linear ticket, wake an agent, make a clip, or speak through a camera (with Speak), with conditions, delays and retries between them, and each run logged. The watch's `notify` list becomes the first step. Built-in steps cover the common cases; nodes for n8n, Zapier and Home Assistant automations cover the rest. A step can tell people or systems; it never switches a device, since control only happens when a person asks (milestone C).
- **Multi-camera stories:** one video built from many moments, across cameras, in time order: pick events or time ranges (or a search such as "the courier, 14:00–14:20") and get a single clip with each camera labelled, shareable by signed link and kept like a saved clip. Following one person automatically from camera to camera ("how did they get in, and which rooms did they enter?") needs matching people across cameras by appearance. That is close to identification, so it comes only after a legal review, never with faces, and off by default.
- **Talk-back ("Speak"):** send audio to a camera's speaker. First push-to-talk in live view and to phone cameras (the capture page plays it), then IP cameras through the bridge (ONVIF backchannel first, then vendor APIs; the bridge converts Opus to G.711), and talking to several cameras at once. For agents, a `speak` tool with text-to-speech, also as a watch action. A new **Speak** permission, off by default like Listen, with every use in the audit log; the rules for agents speaking go in [lawful camera use](lawful-use.md) first.
- **Later:** WHEP egress for third-party players (live view itself ships over the signalling protocol, ADR 0042), H.265, public stream URLs, Kubernetes/Helm.

## Never in scope

Face recognition, plate reading, speech transcription without a legal review,
hardware (the home end runs on boxes people already buy, such as Home Assistant's),
and control of anything that can hurt someone: heaters, ovens, medical devices and
machinery, or any device switched without a person asking.
Senseplane senses, and switches a device only when a person asks; it never decides
to act on its own.
