Date: 2026-10-16. Done-when: *a video-only grant gets an error on `listen`;
masked regions are black in snapshots and model inputs; revocation within
60 s; usage per account matches a known test load within 1%.*

All four measured by `e2e/m6-check.ts` against a running stack (API, media
replaying fixtures, brain with a real vision model, MCP over stdio and over
remote HTTP with OAuth).

## What was built

- **Agents and grants** (ADR 0024): `POST/GET/DELETE /v1/agents` (key shown
  once), grants of sources × senses × window; agent keys limited to
  data-reading routes and watches/clips on granted sources (`403 forbidden`
  elsewhere); live access needs *now* in the window, recorded data must be
  inside it.
- **Audit log**: every authenticated `/v1` request (actor, route, target,
  status), `GET /v1/audit`, module sink `onAudit`.
- **Metering and limits** (ADR 0025): camera time by resolution (segment size
  now reported by media), storage GB-hours (hourly sample), AI checks by kind
  (verify/look/ask/summary/compile, with per-call attribution in the brain and
  dedupe ids), `GET /v1/usage` (period, per-day, per-source, source counts vs
  limits). Quota provider: `maxSources`, `maxActiveSources`, `usageLimits`
  (AI checks pause watches and refuse ask/compile; ingest/storage refuse
  capture and disconnect). `source_limit_reached` (409) on create and join, and
  in media on produce. Self-host default: unlimited.
- **Export and deletion**: `POST /v1/account/export` (JSON with signed media
  links, 1 h download), `DELETE /v1/account` (keys revoked at once, data
  purged by the next 30 s sweep). Shared with the demo's deletion.
- **View-change warning**: the brain keeps a reference view per source when
  masks change and raises `source.view_changed` after 3 failed
  checks 30 s apart (correlation of normalized thumbnails, light-invariant;
  an aspect-ratio change flags at once). The source gets `view_changed_at`
  until the masks are saved again; the console shows "The view has changed…
  Check your masks".
- **Console**: Access (agents, keys, grants, revoke), Audit, Usage, Account
  (name, retention, export, delete) screens; smoke-tested in headless Chrome
  (all render; an agent key is created and shown once).
- **SDK**: `agents`, `usage.get({from,to})`, `account.export/exportStatus/delete`.

## Not covered

- The view-change warning is unit-tested (moved camera flags once after 3
  checks, other lighting never flags, aspect change flags at once); not run on
  a real moved camera.
- Snapshots in object storage aren't in the storage meter (raw segments and
  clips are); they are small.
- The audit log is kept until the account is deleted (no retention setting yet).
- OAuth tokens for remote MCP carry the key; revoking the key or agent cuts
  them off on the next call (tested).
